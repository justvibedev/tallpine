This page describes the GitHub pull-request lane; see [SCM support](/plugins/scm) for GitLab. Authentication is lazy and non-blocking at daemon startup; use `tallpine doctor` to inspect local GitHub readiness.

## Associate a pull request

Claim a PR while spawning or attach it later:

```bash
tallpine spawn --project my-app --name review-fix --claim-pr 42
tallpine session claim-pr 42
# From outside the worker, target it explicitly:
tallpine session claim-pr tallpine-123 42
```

Inside a worker, the one-argument form reads the target session from `TALLPINE_SESSION_ID`.

PR ownership prevents multiple active workers from silently driving the same pull request. Add `--no-takeover` when a conflicting owner must be treated as an error.

A claim attaches ownership metadata and observation. It does not check out the pull request branch; prepare the correct branch/worktree separately before asking the agent to change it.

## Observation and feedback

Tallpine checks active PRs for new CI failures, review feedback, and merge conflicts, then can notify the owning agent. The desktop shows concise summaries, not raw CI logs or full review comment bodies.

## Explicit actions

```bash
tallpine pr merge 42
tallpine pr resolve-comments 42
tallpine review trigger <worker-session-id>
```

Reviewer agents are configured separately from worker agents. See the [capability catalog](/plugins/agents) for the reviewer set and its limits.

## GitHub Enterprise

`<tenant>.ghe.com` (data residency) works without configuration; Tallpine uses `https://api.<tenant>.ghe.com`. For a self-hosted GitHub Enterprise Server, list its host in the daemon's `TALLPINE_GITHUB_ENTERPRISE_HOSTS` (comma-separated, include the port if it has one, omit `https://`); Tallpine then uses `https://<host>/api/v3` and `/api/graphql`.

Each host uses its own token: a `host=token` entry in `TALLPINE_GITHUB_HOST_TOKENS`, otherwise `gh auth token --hostname <host>`. Your github.com token is never sent to another host. A host without a token only fails its own PRs. Restart Tallpine after changing these settings.

```sh
export TALLPINE_GITHUB_ENTERPRISE_HOSTS="github.corp.example"
export TALLPINE_GITHUB_HOST_TOKENS="github.corp.example=YOUR_TOKEN,acme.ghe.com=YOUR_TOKEN"
```

Issue intake (the tracker) stays github.com-only. `*.ghe.io` hosts are no longer recognised automatically; list one in `TALLPINE_GITHUB_ENTERPRISE_HOSTS` if you use it.
