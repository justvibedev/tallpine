## Move to the desktop app

The desktop app is the current supported install. It runs the Go daemon and checks for updates automatically.

Tallpine is a fork of the upstream [Agent Orchestrator](https://github.com/OrchestratorInc/agent-orchestrator). Its npm package is frozen and is not a supported way to install Tallpine; install the desktop app instead.

<Steps>
<Step>

### Preserve active work

Before changing installs, inspect any active sessions and worktrees. Commit, push, or otherwise preserve changes you need. Tallpine will not force-delete dirty registered worktrees, but you should not rely on cleanup as a backup strategy.

</Step>
<Step>

### Open the desktop build

Download the current desktop application from [Installation](/installation).

</Step>
<Step>

### Add or import projects

Open the desktop app and add each local repository you want to use.

Do not copy old session folders into the current database by hand.

</Step>
<Step>

### Verify your tools

Confirm GitHub and at least one agent harness are still authenticated:

```bash
gh auth status
```

Run the agent harness once outside Tallpine if its sign-in expired, then restart the desktop app.

</Step>
</Steps>

## What changed since the npm product

| Older documentation | Current product |
| --- | --- |
| Node.js/Next.js orchestrator | Long-running Go daemon with Electron/React desktop UI |
| Global CLI as the main entry point | Desktop app is canonical; CLI is optional and thin |
| Flat files under `~/.tallpine` | SQLite and all app state under `~/.tallpine` |
| Stored lifecycle status | Status derived at read time from durable facts |
| Runtime plugin matrix and YAML-first setup | Daemon adapters and project settings through the app/API |
| Browser dashboard on port 3000 | Packaged desktop interface over a local daemon |
| Terminal-only sessions | One committed Chat or Terminal UI controller per session; native PTY/ConPTY hosts and legacy tmux compatibility |
| Repository-only work | Git workspaces plus projectless standalone workers |

<span id="historical-package-names" />

Old `agent-orchestrator.yaml` examples and Node plugin packages are not authoritative for the Go rewrite. Reconfigure projects through the desktop app instead of copying unsupported legacy fields.

## Data locations

Current Tallpine state defaults to `~/.tallpine`:

- `~/.tallpine/data` contains durable daemon database files.
- `~/.tallpine/running.json` advertises the supervised daemon process, its socket path and port.
- Managed worktrees and Tallpine metadata remain under the Tallpine home.
- `~/.tallpine/electron` contains the desktop app's Chromium data.
- `~/.tallpine/data/mobile/config.json` contains phone-connection settings. Tallpine writes it with mode `0600` and stores only hashes of credentials. `TALLPINE_DATA_DIR` changes this location.

Do not delete the old or new data directories until you have inspected and preserved active worktrees.

## Updates

Installed desktop builds check for updates on launch and periodically while running. If an update is unavailable through the app, download the latest desktop artifact directly. Running a package-manager update cannot move the frozen npm package beyond `0.10.0`.
